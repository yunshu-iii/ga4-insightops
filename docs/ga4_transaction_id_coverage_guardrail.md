# GA4 交易号覆盖守护记录

## 目的与范围

本守护项防止把订单标识字段的覆盖变化误读为订单、收入、转化或渠道效果的业务变化。它适用于批次 `9a2d8d7c-0f5b-4c57-a54d-98c59b9c5a27` 的 GA4 公开轻量样例，并作为后续完整数据接入时的可复跑基线。

## 数据粒度与规则

- 分母：当天 `is_purchase = 1` 的事件数。
- 分子：交易号非空、非空白且不为 `(not set)`/`unknown` 的 purchase 事件数。
- 覆盖率：分子 / 分母；它是事件级质量指标，不等同于按交易号去重后的规范订单数。
- 阈值：95%。对每个被检测日期，检查当前日和此前最多 7 个自然日的覆盖率。
- 抑制对象：规范订单会话、规范订单、规范订单收入、结账至规范订单率；任一覆盖率低于阈值时，检测结果写入 `is_business_interpretable = 0` 与解释备注。
- 覆盖率指标本身只反映数据质量；订单/收入异常只有在守护通过时才允许输出维度贡献记录。

## 实际证据

守护版日指标运行 `8a9acff4-fa36-4921-b1c0-8d8fe4f2ef9d` 和异常运行 `e9975d26-b3c2-4702-b857-622b6c7da4c1` 的结果如下：

| 检查 | 结果 |
| --- | ---: |
| purchase 事件（v2 日指标 / Staging） | 648 / 648 |
| 有效交易号 purchase 事件（v2 日指标 / Staging） | 190 / 190 |
| 2020-11-01 至 2020-11-10 的有效交易号覆盖率 | 0%（421 个 purchase） |
| 规范订单依赖的日期×指标结果 | 56 条，全部不可作业务解释 |
| v2 统计异常 | 20 条；保留作审计线索 |
| v2 维度贡献 | 0 条 |

11 月 11 日的覆盖率为 43.75%，11 月 12 日为 98.15%，11 月 13–14 日为 100%。由于滚动窗口仍包含 0% 覆盖日期，守护不会在观察窗末尾错误地恢复订单相关业务解释。

## 数据风险与使用结论

严重度为**高**：若绕过守护，前十天的字段缺失会制造“订单、收入从零突然增长”的假象。v2 不删除统计记录，便于发现上游导出或埋点问题，但明确禁止其进入业务 KPI、渠道效果或因果结论。

95% 是公开样例阶段的保守默认值，而不是通用生产 SLA。接入具有稳定交易号的完整数据后，应先确认数据合同、迟到到达模式及业务容忍度，再重跑并复核阈值。
