# InsightOps 项目范围与完成基线

> 项目名称：InsightOps — AI 增长智能洞察平台
> 状态：本地 MVP 已完成；外部发布待办独立管理
> 更新日期：2026-08-25

## 1. 项目目标

为电商增长团队构建一套本地可复跑的分析工作流：从公开样例数据接入开始，依次完成数据质量校验、指标与漏斗建模、异常检测、维度贡献归因、受限 AI 洞察、人工复核与报告输出。

系统要回答的问题包括：

- 核心增长和漏斗指标是否异常；
- 异常最早出现在哪个漏斗环节；
- 哪些渠道或设备是主要贡献维度；
- 应优先验证哪些假设，并监控哪些守护指标。

## 2. MVP 范围

### 2.1 数据源

- GA4 Google Merchandise Store BigQuery 公开匿名化电商事件数据：用于用户、会话、渠道、设备和漏斗分析。
- UCI Online Retail 公开交易数据：用于订单清洗、RFM、复购和 LTV proxy。
- 合成异常数据：仅用于测试；必须带 `synthetic_case=true` 或等效标识。

### 2.2 必做能力

1. Docker Compose 启动 MySQL 8.4。
2. 建立 Raw、Staging、DW Mart、Ops 审计分层。
3. 原始数据不可覆盖；每次数据接入拥有 `batch_id`。
4. 至少 10 条数据质量规则；BLOCKER 失败时阻断下游分析。
5. 至少 3 个核心指标、1 个漏斗、1 个客户价值模型。
6. 使用 rolling median + MAD 检测异常，并输出渠道/设备贡献度。
7. 使用固定工具和 Pydantic 契约构建受限 Insight Agent。
8. 每条 AI 事实结论可追溯到 `run_id`、`metric_id`、日期范围、`query_id` 与证据引用。
9. 提供 Streamlit 页面、HTML/Markdown 报告、测试和演示材料。

### 2.3 固定技术选型

| 层级 | MVP 选型 |
| --- | --- |
| 数据库 | MySQL 8.4 + Docker Compose |
| 语言 | Python 3.11 |
| 数据处理 | pandas、numpy、openpyxl、SQLAlchemy、PyMySQL |
| 配置与校验 | YAML、Pydantic、python-dotenv |
| LLM | OpenAI-compatible SDK；结构化输出与受限工具调用 |
| 应用 | Streamlit + Plotly |
| 测试与质量 | pytest、ruff；mypy 后续渐进引入 |

DuckDB + Parquet 仅可作为早期本地验证或可选复现路径，不作为主数据仓，避免维护两套生产逻辑。

## 3. 明确不做

- 不把公开样例表述为真实企业生产数据或真实落地项目。
- 不让 LLM 计算指标数值、直接修改数据或执行用户拼接 SQL。
- 不声称贡献度归因已经证明因果或根因。
- 不自动执行营销、运营或对外业务动作。
- 不为展示而引入多 Agent、复杂 RAG、分区或预测模型。
- 不在没有真实运行证据时填写转化提升、成本节省等成果数字。

## 4. 核心设计原则

1. **原始数据不可改**：Raw 层仅追加；清洗结果写入 Staging；拒绝记录单独保存。
2. **指标先于 AI**：每个指标必须有公式、粒度、分子、分母、限制与 SQL 模板。
3. **事实先于文本**：LLM 只能接收小型结构化 Evidence Package，不能读取大批量原始行。
4. **每次运行可追溯**：接入、质量检查、指标计算、异常分析、模型调用和报告均记录运行 ID。
5. **人工保留最终判断权**：AI 输出区分事实、统计发现、待验证假设和建议动作。

## 5. Definition of Done

- [x] 从干净环境运行 `docker compose up -d` 能启动数据库。
- [x] 导入 UCI 全量交易数据及 GA4 开发样本；每批数据有来源、hash 与 `batch_id`。
- [x] Raw、Staging、Mart、Ops 审计层都有实际数据和可复跑脚本。
- [x] 数据质量、指标、漏斗、客户价值和异常检测均有测试。
- [x] 合成异常可从派生数据跑到告警、贡献度和洞察报告。
- [x] Agent 无法执行任意 SQL；每个 finding 均有 evidence reference。
- [x] pytest、质量检查和 Golden Questions 能重复运行。
- [x] README、架构图、数据限制、示例报告与 3–5 分钟演示脚本完整。
- [x] 用户明确不需要录制实际 3–5 分钟视频；演示脚本作为可选展示材料保留。

## 6. 交付证据

- 可运行代码仓库与环境说明。
- 指标字典、数据字典、质量报告、核心 SQL 和架构图。
- 一份正常周报与一份合成异常报告。
- 测试报告、CI 结果、Agent trace 与 SQL 优化记录。
- 对外项目描述仅引用实际运行的数据量、通过率、耗时与优化结果。

## 7. 后续执行顺序

1. 第 1 周：环境、数据获取、EDA、指标口径、Raw 接入。
2. 第 2 周：质量门禁、拒绝记录与 Staging 清洗。
3. 第 3 周：会话、订单、漏斗、客户价值 Mart。
4. 第 4 周：异常检测、贡献归因与合成异常。
5. 第 5 周：受限 Agent、证据包、报告与 Streamlit。
6. 第 6 周：测试、性能、CI、演示与对外项目证据。
