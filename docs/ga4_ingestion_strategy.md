# GA4 接入策略与导出预案

## 当前可复跑路径

当前 Google Cloud 项目未关联结算账号，因此不依赖 Cloud Storage。GA4 开发样本使用 Google Drive CSV 导出，并进入本地 MySQL Raw 层。

| 项目 | 当前约定 |
| --- | --- |
| 数据范围 | 2020-11-01 至 2020-11-14，连续 14 天 |
| 粒度 | 一行一个 GA4 事件 |
| 正式输入文件 | `data/inbound/ga4/ga4_ecommerce_events_20201101_20201114.csv` |
| 导出脚本 | `sql/bigquery/03_extract_ga4_events_drive.sql` |
| 导出格式 | Google Drive CSV |
| Raw 层保留 | 文件哈希、批次 ID、源文件行号与所有已导出的事件字段 |

## 字段边界

当前 CSV 保留分析 MVP 所需的事件、会话、页面、设备、国家、首次获得来源、交易号和收入字段；它不包含未展开的 `event_params` 与 `items` JSON。该边界不影响事件漏斗、会话、渠道/设备贡献和收入指标的 MVP 实现。

商品级表现、商品组合分析或额外事件参数只能在补取后开展；在补取前，相关指标必须标记为“数据未覆盖”，不能以空值推断业务结论。

## 后续补取决策

1. 若所需字段能从当前 12 列得到，继续使用本地轻量 CSV，不启用结算。
2. 若只需小范围原始参数或商品数组，修改日期范围后分段导出；每一段单独登记文件哈希与日期范围。
3. 当前优先尝试完整嵌套字段的 7 天 Google Drive CSV 分段；若失败，先降至 1 天连续分段。只有 1 天完整载荷仍无法导出时，才由项目负责人明确接受结算账号并使用 Cloud Storage Parquet 分片；导出完成后下载到本地，停用或清理不再需要的云端对象。

无论采用哪种路径，Raw 层都只追加新 `batch_id`，不能覆盖既有批次。

## 完整公开样例重接入

完整 92 天样例的当前执行方案为 Google Drive CSV 的连续 7 天完整载荷分段导出、严格本地合并及新批次追加。
具体日期表、命名、校验和再处理顺序见 [完整 GA4 重接入说明](ga4_full_refresh.md)。
